# بنية المادة العلمية — ملف واحد لكل وحدة

> `src/data/units/unit-XX.json` هو **المصدر الوحيد** لمادة الوحدة.
> المخطط: `src/data/schema/unit.schema.json`. المدقّق: `npm run data:check`.

---

## 1. لماذا ملف واحد؟

كانت الوحدة موزّعة على خمسة ملفات (`_standard` · `_advanced` · `_mindmap` ·
`_quiz` · `_questions`)، لكل واحد شكل مختلف، والمُطبّع يفهم ستّة أشكال للإجابة
الواحدة. النتيجة: إضافة وحدة تحتاج خمسة ملفات متزامنة، وأي مفتاح ناقص يظهر
فراغًا في الواجهة بلا خطأ.

الآن: ملف واحد، مخطّط واحد، ومدقّق يفشل بصوت عالٍ قبل الالتزام.

```
src/data/
├── schema/unit.schema.json   ← عقد الملف (JSON Schema 2020-12) + شرح كل حقل
└── units/
    ├── _template.json        ← قالب للنسخ (لا يُحمَّل في التطبيق)
    ├── unit-01.json
    ├── unit-02.json
    ├── unit-03.json
    └── unit-04.json
```

التحميل: `src/lib/data-loader.ts` يستورد الملفات ويحوّلها إلى `NormalizedUnit`
(ترطيب فقط، بلا تخمين). الأنواع في `src/lib/types.ts`.

## 2. الهيكل

```jsonc
{
  "$schema": "../schema/unit.schema.json",
  "schemaVersion": 2,

  "source": { "curriculum": "…", "subject": "…", "reviewedBy": null, "updatedAt": "2026-10-25" },

  "unit": {
    "id": 1,
    "slug": "aqidah",                 // ثابت بعد النشر: تقدّم الطالب مرتبط به
    "title": "الوحدة 01: …",
    "shortTitle": "…",
    "badge": "الوحدة 01",             // الشكل إلزامي: «الوحدة NN»
    "field": "العلوم الإسلامية",
    "timeAllocation": "ساعتان",
    "targetAudience": "جميع الشعب…",
    "learningObjective": "الكفاءة المستهدفة…",
    "mindmapImage": "/lessons/unit01_mindmap.webp",
    "video": { … }                    // اختياري — §4
  },

  "lesson": { "sections": [ { "key", "title", "content" } ] },
  "mindmap": { "root": { … } },
  "flashcards": [ { "id", "question", "answer", "section?" } ],
  "cloze": [ { "id", "concept_id", "concept_title", "text_with_masks", "answers" } ],
  "quiz": [ { "question_id", "question", "options[4]", "correct_answer", "explanation", "hint?" } ],
  "questionBank": [ { "id", "category", "question", "modelAnswer", "scoringRubric?" } ],
  "revision": { "lastMinute", "summary", "rules", "differentiation", "previousBac" },
  "proofs": [ { "id", "surah", "ayah", "text", "anchor?", "keywords?", "note?" } ]
}
```

### قواعد ثابتة يفرضها المدقّق

| القاعدة | السبب |
| --- | --- |
| `badge` = «الوحدة NN» | يُعرض في القوائم والفوتر كما هو |
| `slug` لاتيني صغير | معرّف ثابت للروابط والمفاتيح |
| كل عقدة **طرفية** في الخريطة لها `details` | كانت 39 عقدة بلا شرح تظهر فارغة |
| الخريطة بلا `proof`/`keywords`/`note` | الخريطة عناصر مفهومية فقط؛ الإضاءات مكانها الدرس |
| `options` أربعة و`correct_answer` واحدة منها | خلط الخيارات عند العرض يعتمد على هذا |
| أقنعة `{mask1}` = مفاتيح `answers` | وإلا يظهر فراغ بلا إجابة |
| معرّفات البطاقات والأسئلة فريدة | التقدّم يُخزَّن بمفتاح `u{unit}_c_{id}` |
| لا محور `key` فيه `methodolog` | القواعد المنهجية مكانها «المراجعة السريعة» |
| لا «ورش» في أي حقل | نُسب نصّ شرعي إلى رواية، وهو مرفوض |

## 3. `lesson.sections[].content` — أشكال المحتوى المفهومة

`content` يقبل نصًّا أو كائنًا أو قائمة. الكائن يُقرأ بمفاتيحه:

| المفتاح | العرض |
| --- | --- |
| `title` / `official_title` | عنوان فرعي داخل المحور |
| `linguistic_definition` | كتلة «التعريف اللغوي» |
| `idiomatic_definition` | كتلة «التعريف الاصطلاحي» |
| `definition` | كتلة «التعريف» |
| `explanation` | شرح عام |
| `quranic_proof` / `prophetic_proof` | **شاهد** (اقتباس بخطّ نسخي + زرّ نسخ) |
| `proof_anchor_phrase` | «محل الشاهد» |
| `effects` | قائمة عناصر (عنوان + شرح) |
| أي مفتاح فيه `note` · `tip` · `guidance` | بطاقة **إضاءة / فائدة** لا عنصرًا يُحفظ |

> لا تُضِف عنصرًا مفهوميًا إلى المحور ثم تنساه في الخريطة: الخريطة هي **ملخّص
> المحاور**، والاختبار يمنع أن تحمل شواهد.

## 4. الشرح المرئي (اختياري)

أضف `unit.video` فيظهر **خطوة أولى في مرحلة «استيعاب»** قبل نصّ الدرس.
إن غاب الحقل فلا تظهر الخطوة إطلاقًا (لا زرّ معطّل ولا مكان فارغ).

### 4.1 فيديو مستضاف (YouTube/Vimeo)

```json
"video": {
  "provider": "youtube",
  "id": "dQw4w9WgXcQ",
  "title": "شرح الوحدة 01 — مدخل العقيدة",
  "duration": "12:40",
  "poster": "/lessons/unit01-video.webp",
  "chapters": [
    { "at": "00:00", "title": "المدخل" },
    { "at": "03:20", "title": "التعريفات" }
  ]
}
```

- يُستعمل نطاق `youtube-nocookie.com` (بلا كوكيز تتبّع)، ولا يُحمَّل أي شيء قبل
  نقر الطالب: الغلاف + زرّ التشغيل فقط.
- `chapters` تُعرض قائمة مرجعية (لا انتقال) لأن التحكّم في مشغّل خارجي يحتاج
  واجهة برمجية من الطرف الثالث.

### 4.2 ملف فيديو داخل المشروع

```json
"video": {
  "provider": "file",
  "src": "/lessons/unit01.mp4",
  "captions": "/lessons/unit01.vtt",
  "title": "شرح الوحدة 01",
  "duration": "12:40",
  "chapters": [{ "at": "00:00", "title": "المدخل" }, { "at": "03:20", "title": "التعريفات" }]
}
```

- `captions` **إلزامي** هنا: فيديو بلا تفريغ عربي يخسر الطالب الأصمّ، ويخسر
  البحث داخل النص.
- مع `provider: "file"` تصبح الفصول أزرار انتقال حقيقية (seek).
- ضع الملف في `public/lessons/` واحتَرِم ميزانية الأداء: < 25MB للفيديو
  التعليمي القصير، و`poster` دائمًا.

### 4.3 ما لا يفعله الفيديو

لا يُضاف إلى مسار التقدّم كمهمّة مقيسة (لا يُحسب في نسبة الإتقان)، ولا يستبدل
القراءة: يظهر بجانبها كمرافق. سبب ذلك أن قياس «المشاهدة» غير موثوق، وتقدّم
الطالب يجب أن يبقى مبنيًا على أفعال يتحقّق منها التطبيق.

## 5. سير العمل

```bash
cp src/data/units/_template.json src/data/units/unit-05.json
# حرّر الملف، وأضف meta الوحدة في src/lib/units-meta.ts (id/slug/title/shortTitle/badge)
npm run data:check        # يفشل بصوت عالٍ عند أي نقص
npm run verify            # typecheck + lint + data:check + الاختبارات
npm run dev               # ثم: /units/5
```

`data:check` يطبع جدولًا بعدّادات كل وحدة:

```
وحدة | محاور | بطاقات | فراغات | QCM | بنك | شواهد | فيديو
   1 |     3 |     49 |      8 |  20 |  30 |     6 | youtube
```

وأي خطأ يظهر بسطر يشرح السبب، لا برمز:

```
✗ unit-05.json
   - QCM Q07: الإجابة الصحيحة ليست بين الخيارات
   - mindmap: العقدة الطرفية «leaf_3» بلا شرح
```

## 6. الفهرس والملف: لماذا يتكرّر العنوان؟

`src/lib/units-meta.ts` يحمل `id/slug/title/shortTitle/badge` لكل وحدة، لأنه
يُستعمل في الشريط العلوي والفوتر **بلا** تحميل بيانات الوحدات كاملة (حجم
المادة ٣٢٠KB). الملف يكرّرها لأن المادة يجب أن تكون مكتفية بذاتها.

الانفصال بينهما خطر (عنوان في القائمة ≠ عنوان في الوحدة)، ولذلك:
`validateUnitFile(file, { meta })` يقارن الحقول الخمسة، و`npm run data:check`
يقرأ الفهرس من المصدر ويقارن. أي تعارض يُفشل الفحص.

---

## 7. الشواهد (`proofs`)

مادة محفوظة غير معروضة بعد: نصّ الآية/الحديث + محلّ الشاهد + كلمات الاستخراج +
إضاءة تعليمية. تُستعمل عندما يُبنى قسم «الشواهد» داخل الدرس. لا تُحذف: هي أصل
الاستخراج في أسئلة البكالوريا.

---

## 8. سجل الهجرة (الجولة 21)

- الملفات الخمسة القديمة حُذفت بعد مقارنة كاملة: ناتج التطبيع من الملفات
  الجديدة **مطابق حرفيًا** لناتج المُطبّع القديم (محاور، بطاقات، فراغات، QCM،
  بنك الأسئلة، الخريطة، المراجعة) لكل وحدات المشروع الأربع.
- الأعداد بعد الهجرة: 4 وحدات · 14 محورًا · 131 بطاقة · 24 فراغًا · 70 QCM ·
  104 أسئلة بكالوريا · 16 شاهدًا.
- حُذفت الحقول غير المستعملة من البيانات (`flashcards_sample`,
  `question_concept_junction`, `supported_app_modes`…) وبقيت الشواهد لأنها مادة.
- سكربت الهجرة كان مسار Next مؤقتًا يستدعي المُطبّع نفسه ثم حُذف؛ لا منطق
  تطبيع مكرّر في المشروع.
